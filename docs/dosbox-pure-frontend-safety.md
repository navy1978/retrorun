# DOSBox Pure frontend safety

The 1.0-preview6 core can query internal options without an exported key. GET_VARIABLE now checks null data/key, clears unavailable values and returns false, so the core uses its own default. The previous code constructed a std::string from nullptr. `tests/null_core_option_fixture.cpp` exercises null data, a null key and an unknown key with a stale value against the actual frontend. On RG351MP the previous FE failed initialization with exit 73; the corrected FE prints NULL_CORE_OPTION_FIXTURE_PASS and deliberately rejects content afterward (exit 69).

Native Pixel Perfect also needs a contained fractional fallback when a source is larger than the display. The DOS menu switches to 768×528; forcing 1× produced a destination (-64,-24,768,528) on 640×480 and repeated RGA failures. The native path now uses the shared fitAspect helper in that case (640×440 at 0,20). Normal fitting integer scales and SDL behavior stay unchanged. `tests/aspect_viewport_test.cpp` includes the reported dimensions.

OpenAL startup previously required 2646 frames for a 60ms prebuffer at 44100Hz. Four DOS batches of 629 frames fill every buffer with only 2516 frames. Playback never began, so the next batch waited two seconds for buffers that could not be processed. The prebuffer policy now starts when the target is met OR all available buffers are queued, still requiring at least two buffers and respecting pause. This also applies on underrun recovery. It adds no lock, allocation or logging per frame. `tests/openal_prebuffer_test.cpp` covers DOS 70Hz, ordinary 60/50Hz and small-batch/large-target boundaries; it is included in make test.

Build verification: isolated accepted input/theme source plus these scoped patches, existing AArch64 SDK, GO2 and SDL2 builds passed. Unrelated platform/video experiments in the ordinary checkout were excluded. Portable viewport/prebuffer tests passed on macOS.

RG351MP verification with the user's Pixel Perfect runtime settings and DOSBox Pure: 300 core frames and 300 presented frames completed, exit 0, no RGA rejection. Average audio callback time was 0.062ms. The earlier short probe produced five frames and a two-second audio submit wait, so that initial startup-only probe was insufficient to validate the changing DOS menu. This is an automated menu/render/audio test; interactive controls and sustained gameplay still require user validation. Benchmark mode skipped SRAM/save-state writes and used a separate save directory.
